# marketing/ — the media worker

The worker half of the marketing engine (design doc §12). It is its **own Railway service**:

| File | Role |
|---|---|
| `Dockerfile` | the worker image — same Debian base + ffmpeg as the web app, plus Kokoro + torch-CPU with the weights and the `af_heart` voice BAKED in (`HF_HUB_OFFLINE=1` at run time); never the web app's requirements |
| `railway.toml` | config-as-code for that service: cron schedule, start command, watch patterns |
| `requirements.txt` | the worker's direct Python deps: httpx, torch 2.6 (CPU), kokoro/misaki 0.9.4, spaCy's English model (hash-pinned), Pillow, fontTools |
| `constraints.txt` | EVERY package of the image pinned to the versions the 2026-09-26 spike measured (applied with `-c`); keep it in step with `requirements.txt` |
| `main.py` | entrypoint: ET gate → claim → preflight → stages → checkpoint → exit. One pipeline per tick, over two run LANES (migration 210): yesterday's resumes first (each only before its lane's hour), then today's `main` run (`POST /runs/claim`, from `MARKETING_RUN_HOUR_ET`), then today's `spotlight` run (its own route `POST /lanes/spotlight/claim`, from `MARKETING_SPOTLIGHT_HOUR_ET`; the web answers `not_scheduled` unless the day is a spotlight day, and an older web's 404 (or 405) skips the lane with a WARNING), a fresh claim nonce per claim, and the run handed over must be of the lane asked for. Stages: `selected` and `scripted` (kick-and-poll the web side for the day's script), `voiced` (Phase 3), `rendered` and `assets_ready` (Phase 4). A finished run closes `media_ready`. The claim declares all eight `WORKER_CAPABILITIES` (`post_image`, `news_templates`, `layouts_2b`, `video_v2`, `layout_feature`, `post_art`, `look_v23`, `theme_angles`; pinned equal to `app.schemas.marketing.WORKER_CAPABILITIES`), and the web credits a run's holder only with what it declared: a template (company news) day needs `news_templates`; a theme post (`grid`) needs `layouts_2b`; Batch 2's video features are frozen into a run only for a `video_v2` holder; a `feature` picture goes only to a `layout_feature` holder (2026-11-15 — no series draws one since the owner's 2026-11-20 decisions, so today it gates nothing); per-post art is made only for a `post_art` holder (2026-11-16; never required — and art is used nowhere since the 2026-11-20 decision); `look_v23` (2026-11-19, the restyle news-v23) keeps earnings (its table), company stakes (each stake's basis label) and the insider LIST (its rows' detail lines) on the day's chain and brings the ticker chips, the list covers, the Money Map cover's figure label and a loss year's costs card (without it: none of those, and a 13F picture cut to five rows); `theme_angles` (2026-11-20) brings the theme angles 2-5 (`ranked`, `figures`, `ledger`, `tally`) with the theme's chips, decoration and list cover (without it: angle 1, "how they make money", only). A media stage starts only with `STAGE_START_MARGIN_SECONDS` (14 min since 2026-11-16: the render's worst case is 799.25 s — the post image's share `IMAGE_RENDER_SECONDS` 40 for the art's draw-then-fallback, plus the art's one download) of the 30-minute tick left. The preflight checks every ffmpeg filter the render can emit (`RENDER_FILTERS`, including the push-in's `zoompan`/`tpad`) |
| `voice.py` | the `voiced` stage: Kokoro in a child process (`python -m marketing.voice child …`), seeded, bit-exact AAC, word timings in the audio asset's metadata, the pointer in the checkpoint PATCH. Skipped on a day no outlet gets the video (an image-only day included) |
| `render.py` | the `rendered` stage (read back the verified narration, download + sha check, cards, captions, one ffmpeg call, register the video with what it drew; since drop 1 also the 4:5 post image, registered as a `card` with `image_role` `post_image`) and the `assets_ready` stage (record each outlet in the run's FROZEN `post_formats`, falling back to `POST_FORMAT` for an older script). Batch 2: reads the run's frozen `video_features`, `data_card_slot` and `end_card_cta` from the script read-back (through `cards.video_features` / `cards.data_card_slot` / `cards.end_card_cta`) and keys the video on them (RENDER_STAGE_VERSION render/v6 since 2026-11-15: the `feature` picture and, with workstream C, the per-post art — bumped once for both; render/v7 since 2026-11-19: the approved look, news-v23, and the script's `series` in both reuse keys). Workstream C: the read-back's `art` is resolved ONCE per stage (`art.py`) and drawn on the `feature` picture's band and on the opening card; each surface that draws it burns `AI illustration` and declares the art's sha256 (`metadata.art_sha256` / `opening_art_sha256`, None when not drawn; `art_skipped` / `opening_art_skipped` say why not), and both reuse keys carry it; a push-in render that fails with `RenderFailed`/`RenderRejected` (never a timeout, the memory limit or a card that cannot fit) renders ONCE more with card 0 still, inside the same ffmpeg budget, and records `metadata.push_in` False plus `push_in_fallback` |
| `cards.py` | pure: the 1080×1920 PNG cards (text, stat, disclaimer; the brand card only when a script has no text card — videos open on the first text card since drop 1; a TEMPLATE script's video opens on its company `opening` card — kicker, logo disc(s), chip, figure (with its label under it, news-v23 `figure_label`), headline; a list post's cover is its list — then one text card per narration line, drop 2a; with per-post art, workstream C, it opens on a band of the art across the card's top (`OPENING_ART_W` × `OPENING_ART_H`), the one logo disc on its bottom edge, the chip, headline and figure under it and `ART_LABEL` ("AI illustration") burned on the band — the plain opening card whenever that cannot be drawn, never a skipped day) and the 1080×1350 baseline-JPEG post image (title + paragraphs + footer, ≤ 950,000 bytes); company logos are drawn unaltered on discs, a wordmark (the company name) when a logo is missing; never truncates. THE LOOK (news-v23, CARD_RENDER_VERSION cards/v6, 2026-11-19, the approved FINAL_REFERENCE mocks): `look.py` (palette, gradient + gold glow, the brand row — the vendored Caydex tile + "Caydex" top-left, the kicker pill right — the two-tone UPPERCASE headline — split only at a sentence or clause boundary, else one block whose last line is gold — warm cards, chips, logo discs (white; dark for a logo made for a dark background; the plate's own colour, sized by its marks, for a logo served on a light plate), the short footer, the colour rules by series) and `card_layouts.py` (every video card kind and the lesson picture); on video the brand row sits 140 px from the top and nothing is drawn in the safe bottom 420 px. `LAYOUTS` and the closed `image_spec` schema mirror `app/services/marketing/template_onscreen.py` (pinned by tests). Batch 2 video features, each falling back to the previous video, never to a skipped day: (1) a lesson may open on its HOOK card — the accepted hook alone over the narrated hook (the server freezes it only for a hook that passes its checks alone; one that is not one drawable string, lacks a glyph or does not fit opens on the first content card as before); (2) a template's DATA card replaces the text card the read-back's `data_card_slot` names (a fact card, never a hedge) with the day's post image laid out natively in the card text zone — below the 22 px floor that text card stays, and with no slot there is no data card; (3) the end card draws the read-back's `end_card_cta` ("Search Caydex on the App Store"), or `caydexinvest.com` when it is absent |
| `news_layouts.py` | pure: a template script's post image from its closed `image_spec`, in the look (`look.py`) — the `rows` layout (drop 2a; since news-v23 each list series draws its own: the Form 4 insider LIST and roundups, `_lay_insider_list` — logo, name with its ticker chip, roles, the green total and, on the picture only, the grey "… a share, as filed" detail line; the 13F list with "Closed out"; the earnings table; the Congress count list; the company stakes list; and the theme's list cover), `spotlight` (the one-company Form 4 picture — drawn by no series since the owner's 2026-11-20 decisions, kept for an older web during a deploy), `bars` (the Money Map; owner decision 2026-11-20, a LOSS year's second card is the costs card — `cards.COSTS_KEYS`: revenue against the longer red costs bar on one scale, the net loss past the revenue line, `costs_bar_widths` — and its video cover `_lay_costs_cover`), `pair`/`grid` (drop 2b, shipped 2026-10-10: `grid` is the theme post's angle 1; `pair`, company stakes' picture until news-v23, is drawn by no series now), `ranked`, `figures`, `ledger` and `tally` (news-v23 phase 3, 2026-11-20: the theme angles 2-5 — who's biggest, growth + profit, the insider scorecard, Congress — under `theme_angles`) and `feature` (2026-11-15; drawn by NO series since the owner's 2026-11-20 decisions, kept for a future series: an ART BAND across the card's top — `cards.FEATURE_BAND_*`, 952×440, the kicker pill and the logo plate on a flat panel, or (workstream C) the per-post art centre-cropped into it with the plate at its bottom-left and `AI illustration` at its bottom-right; a picture whose art cannot be drawn renders again without it, byte for byte today's — then the name + chip, the figure, its label, the headline and 1-4 fact rows; the band height was chosen by a worst-case fit test), declaring exactly the server's allowed strings; never draws the `image_post` alt text. It also lays the same picture out as the video's DATA card (`DATA_CARD_FRAME`, `DATA_CARD_MIN_PX` = 22) — never a `feature` picture (`cards.DATA_CARD_LAYOUTS`: its facts carry the filing's cost per share, which stays off video) |
| `look.py` | pure: the approved LOOK (news-v23, 2026-11-19, ported from the FINAL_REFERENCE design kit) every post picture and video card is built from — the palette and its colour rules (GREEN a purchase / increase / new holding / profit, RED a sale / decrease / closed-out holding / loss, GOLD neutral emphasis), the navy→black gradient with its gold glow, the brand row (the vendored Caydex tile + "Caydex" top-left, the kicker pill right-aligned), the two-tone UPPERCASE headline, warm cards, ticker chips, logo discs (white, or dark for a logo made for a dark background — `logos.disc_tone`) and the one short footer line; deterministic, every ink box checked inside its region |
| `card_layouts.py` | pure: lays out every 9:16 video card kind in the look — the template `opening` cover (the headline beside the company plate, then the figure on a warm card with its label inside it; a list post's cover is its list), `text`, `hook`, `stat`, the `disclaimer` end card with its CTA, `brand` — on video the brand row 140 px from the top, nothing in the safe bottom 420 px — and the 1080×1350 LESSON picture (the title two-tone, each paragraph on its own warm card on a gold dot rail, the "INVESTING LESSON" pill); `cards.py` keeps the contract (what each kind draws and declares, the ramp, the bytes) |
| `theme_art.py` | pure: the weekly theme post's text-free gold DECORATION in the picture's top-right glow, one per theme (`cards.THEME_ICONS`: chip, bolt, wafer, shield, radar — the spec's `icon`, sent only to a `theme_angles` holder); it draws no string, so it never reaches the server's allow-list, and `extent` keeps it clear of every line of text |
| `logos.py` | the template day's company logos (news-v23: a logo made for a dark background is KEPT and drawn on the dark disc — `disc_tone`; a wordmark only when it shows whole on neither disc; `opaque_plate` / `light_plate` / `plate_marks` find a logo served on an opaque plate): only `https://<bucket origin>/storage/v1/object/public/marketing-media/logos/<sha[:32]>.<png|jpg>` is fetched (origin = the run's verified narration URL), sha256-checked, decoded under a 2048² pixel bound, within one 60 s budget; any failure is a wordmark, never a skipped day. A logo made for a dark background (≥ 30% transparent with its visible ink spanning < 60% of its solid box on white — FMP's GameStop and Amazon) is drawn whole on the DARK disc; a logo that shows whole on neither disc, or carries a baked light "transparency" checkerboard (Boston Scientific's), draws the WORDMARK |
| `art.py` | workstream C, the run's per-post ART (owner decisions 2026-11-15): only `https://<bucket origin>/storage/v1/object/public/marketing-media/art/<sha[:32]>.jpg` is fetched (the logos' origin rule), within ~8 s, sha256-checked against the read-back, its size and bytes the read-back's, decoded header-first under its own 2752×1548 pixel bound (a JPEG, one frame, RGB or L); any failure is today's drawing — art never skips, fails or delays a day. Its bounds mirror `app/services/marketing/post_art.py` (pinned by tests) |
| `video.py` | the timeline, the ffmpeg argv, the runner and the ffprobe gate — never `-shortest`; the push-in (Batch 2): card 0 zooms 1.00 → 1.03 over 45 frames (1.5 s) on a bit-exact 2× upscale, then holds (`push_in_filters`; frame-identical on ffmpeg 5.1.10 and 7.0) |
| `timings.py` | pure: engine tokens → the script's own display words with times |
| `captions.py` | pure: timed words → the ASS caption file libass burns; a phrase never ends on a figure before its scale word ("$50 \| billion"); under a lesson's hook card the hook line is not captioned twice (`without_hook_card_words`) |
| `preview.py` | local check: `./venv_marketing/bin/python -m marketing.preview` (from `backend/`) renders the full video — voice, cards, captions — into the gitignored `out/`; `--art-file ART.jpg` draws a local 16:9 JPEG as a template's per-post art (no fetch, no spend) |
| `assets/fonts/` | Inter Bold (static, OFL) for the cards, the caption burn and measuring |
| `assets/brand/` | the Caydex logo for the disclaimer card (and the fallback brand card; the image copies only `marketing/`) |

Railway setup (service `marketing-worker`, all in the DASHBOARD — Railway lets no new service use a
config file, and it ignored a custom Dockerfile path): **Root Directory `/backend/marketing`** (the
build context; Railway auto-detects this folder's `Dockerfile`), **Cron `15 * * * *`**, **Restart
Policy Never**, no health check, Watch Paths `/backend/marketing/**`, **8 GB of memory** (4 GB until
2026-10-30: the container peaked at 2.6 GB during the voice stage on 2026-10-01 and at 3,345 MB on the
2026-10-28 earnings day — its Kokoro child at 2,206 MB, the rest page cache; the render runs after the
voice child has exited). Railway bills memory used, not the limit. The run-health alert reads the limit
the preflight records, so it follows this setting. `railway.toml` records these values.
Environment: `MARKETING_API_BASE_URL` (the web's public URL, `https://caydexinvest.com`),
`MARKETING_WORKER_TOKEN`, `MARKETING_RUN_HOUR_ET` (mirrored on the web service under the same name
for its run-health timing — change both together), `MARKETING_DRY_RUN` (optionally
`SUPABASE_PUBLISHABLE_KEY`) — and **no** Supabase secret, **no** social or bot token. Knobs, all
optional: `MARKETING_SPOTLIGHT_HOUR_ET` (default 10; the hour of the spotlight lane, the second run of a
spotlight day — mirrored on the web service under the same name, change both together; a value that is
not a whole hour before `MARKETING_RUN_HOUR_ET` skips only that lane), `MARKETING_RUN_LANE` (manual runs
only: `main` or `spotlight` keeps every tick to that lane, unset = both; anything else claims nothing),
`MARKETING_TTS_VOICE` (default `af_heart`; only a voice baked into the image works — the
preflight reports it), `MARKETING_TTS_SPEED` (1.0), `MARKETING_TTS_THREADS` and
`MARKETING_RENDER_THREADS` (else the container's CPU quota), `MARKETING_MAX_VIDEO_SECONDS` (75,
mirroring the web setting).

Nothing here imports `app.*`. The web-side half (ledger, publisher loop, review bot, content
selection, the writer, its validators and the compliance judge) is `app/services/marketing/`; the
worker reaches the database only through `app/api/v1/endpoints/marketing_internal.py`, and every
call after its claim presents that claim (`X-Marketing-Claim`). It never sees a caption: copy is
server-authored and recorded by `create_posts` from the accepted script. The server checks what the
video SAYS (the narration's timed words must be the accepted script's) and what it DRAWS (the video
declares every on-screen string; only the script's cards, its disclaimer card, the end card and — while
a video feature is frozen — that feature card's strings (the hook; the post image's) are allowed, and the
disclaimer card is required).

Order of operations for the first deploy: deploy the web service FIRST → create this service and
set the SAME `MARKETING_WORKER_TOKEN` on both → watch the first in-window tick: a `marketing_runs`
row with `metadata.preflight.voice.ready` and `metadata.preflight.render.ready` true, then
`marketing_scripts` accepted, `audio` and `video` assets `ready` (on a day with a video outlet),
`marketing_posts` rows `pending_review`, and the run closed `media_ready`. Each stage's checkpoint
`timings` carry its wall time and peak memory (`<stage>_children_maxrss_mb`, and
`<stage>_cgroup_peak_mb` where the kernel reports it). A day can also close `skipped` with a
reason that says why: `rest_day`, `content_rejected`, `writer_unavailable`, `empty_pool`,
`source_ineligible`, `narration_too_long`, `unrenderable_text` (a glyph the font lacks, or a card
that cannot fit), `judge_not_enforced` (the web runs MARKETING_JUDGE_MODE other than `enforce`),
`template_refused` (the day's template post failed the server's re-check at `create_posts`, or
MARKETING_CONTENT_CLASSES no longer lists its class), `nothing_qualified` (a spotlight day whose series
chain found no record — it skips, never the lesson; logged at INFO). A
409 `MARKETING_RUN_NOT_HELD` means this tick no longer holds the run; the worker logs a WARNING and
exits 0. Never set `MARKETING_RUN_DATE` to a future date: the backend refuses it (a claim is a
UNIQUE `(run_date, lane)` row, so a sample run would consume the real day).
